→

★
그 결과 비슷한 뜻의 토큰이 비슷한 벡터가 된다 — 의미가 좌표에 담긴다.
임베딩 = 토큰→벡터 대응표
# 어휘 하나당 벡터 한 줄 (예: 768차원)

  "queen": [0.19, -0.40, ..., 0.11],  # king과 가까움
  "apple": [-0.66, 0.02, ..., 0.51],
}

한 줄
임베딩은 '토큰 → 의미를 담은 좌표'로 바꾸는 첫 단계다. 이후 계산은 전부 이 벡터 위에서 일어난다.

생성 루프 — 개념
ids = tokenize("고양이가 쥐를")
for _ in range(N):
    logits = model(ids)          # 트랜스포머
    probs  = softmax(logits[-1]) # 다음 토큰 분포
    nxt    = sample(probs)       # 하나 고르기
    ids.append(nxt)              # 이어 붙이고 반복

pydantic_schema.py
from pydantic import BaseModel, Field

class Ticket(BaseModel):
    category: str = Field(description="문의 분류")
    urgent: bool  = Field(description="긴급 여부")
    summary: str  = Field(description="한 줄 요약")

model.with_structured_output(Ticket)
→
Pydantic 모델로 필드·타입·description을 정의한다.
→
그 description이 모델에게 지시로 전달돼, 각 필드를 무엇으로 채울지 안내한다.
★
타입이 안 맞으면 검증에서 걸린다 — 앱이 신뢰할 수 있는 출력.

CH7확장▶ 51-Tool-Calling

모델이 직접 함수를 부른다

tools.py
@tool
def get_weather(city: str) -> str:
    "도시의 현재 날씨를 반환한다"
    return weather_api(city)

llm_with_tools = model.bind_tools([get_weather])
# 모델이 필요하면 get_weather("서울") 호출을 요청
→
LLM은 계산·조회·행동을 직접 못 한다. 함수를 도구로 등록해 두면 모델이 필요할 때 호출을 요청한다.
→
앱이 그 함수를 실행하고 결과를 모델에 되돌려 준다 — 7강 에이전트 루프.
★
이게 LLM에 '손'을 달아주는 방법. LangChain @tool로 등록한다.

CH7확장▶ 52-Agents

판단 → 도구 → 관찰 → 반복

→
에이전트 = LLM이 어떤 도구를 언제 쓸지 스스로 정하고, 결과를 보고 다음을 결정하는 루프.
→

★

정리
도구가 하나면 도구 호출, 스스로 고르고 반복하면 에이전트다.

트랜스포머에서 에이전트까지

안

트랜스포머

다음 한 토큰을 고르는 엔진 — 어텐션(Q·K·V)이 문맥을 읽고, 가중치에 지식이 새겨진다.

다루기

프롬프트·체인

가중치는 그대로, 입력으로 다룬다 — few-shot·system·CoT, LangChain(LCEL)으로 엮는다.

앱으로

구조화·에이전트

자유 텍스트를 데이터로(Pydantic), 도구·에이전트로 행동을 붙인다.

한 줄
LLM은 '다음 토큰을 고르는 트랜스포머'다. 그 안은 어텐션, 그 밖은 프롬프트 → 체인 → 구조화 출력 → 도구·에이전트. 실습 노트북으로 손에 익힌다.
